How NDM downloads a file

NDM is fast because it never waits on a single connection. Here is what happens between clicking a link and finding the finished file.

Parallel parts

NDM's first request downloads the file itself. When the server allows fetching parts of a file, NDM opens more connections, one at a time, each fetching a different part. When a connection finishes its part early, it picks up some of the work still left, so every connection stays busy until the very end.

The progress window shows every connection as a row, and the strip under the progress bar shows which parts have arrived.

Resuming

A stopped or broken download keeps its parts. Before resuming, NDM checks a few of the bytes it already has against the server's copy; if the file on the server has changed, NDM tells you instead of joining two different files.

Servers that don't allow parts can only start again from the beginning.

Connections and speed

The number of connections per download is set in Options → Connection, where you can also give single servers a lower limit. The speed limiter (right-click the notification area icon) caps the total speed of all downloads, so the rest of your network stays usable.
